Priority Definitions

  • P0 - Drop Everything: App crashes, core flow broken, data loss, security issues. Fix immediately.
  • P1 - Fix This Week: Features that give wrong results, significant UX friction. ROI Score 70+. Fix within 1-2 weeks.
  • P2 - Fix Next Sprint: Minor UX annoyances, edge cases affecting <10% users. ROI Score 40-69. Fix within 1 month.
  • P3 - Backlog: Nice-to-haves, visual polish. ROI Score <40. Fix when slow.

ICE + ROI Scoring Framework

For every bug or feature request:

  • Impact (1-10): How much does this affect UX or revenue?
  • Confidence (1-10): How sure are we this matters?
  • Ease (1-10): How easy is it to build?
  • ROI Score = (Impact × Confidence) / Ease

Example: Bug causing 20% drop-off at checkout → Impact: 10, Confidence: 9, Ease: 7 → ROI: (10×9)/7 = 12.9 → P1

Decision Framework for New Features

When someone suggests a new feature, ask:

  1. Does this directly increase purchases or reduce drop-off? (If no → backlog)
  2. Can we build an MVP in <40 engineering hours? (If no → break it down or cut)
  3. Does this support our brand partnership pitch? (If yes → bonus points)

If a feature doesn't score 2/3 "yes" answers, defer it to 2027.
